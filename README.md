# HMS Backend

Spring Boot REST API for authentication, patients, doctors, OPD, laboratory, IPD,
pharmacy billing, and discharge workflows. Production is configured for PostgreSQL
on Neon and deployment as a Docker web service on Render.

## Local development

Requirements: Java 17 and PostgreSQL.

1. Create a PostgreSQL database named `hms`.
2. Copy `.env.example` values into your shell or IDE environment and replace the
   placeholders. For local PostgreSQL, use:

   ```text
   DB_URL=jdbc:postgresql://localhost:5432/hms
   DB_USERNAME=postgres
   DB_PASSWORD=your-local-password
   ```

3. Run:

   ```powershell
   .\mvnw.cmd spring-boot:run
   ```

The API base path is `/api/v1`; health is available at `/actuator/health`.

## Create the free Neon database

1. Create a Neon project and database.
2. Open **Connect**, enable the pooled connection, and select **Java**.
3. Put the JDBC URL, role, and password into Render as `DB_URL`, `DB_USERNAME`,
   and `DB_PASSWORD`. The URL must begin with `jdbc:postgresql://` and include
   `sslmode=require`.
4. Keep these values only in Neon/Render; never commit them.

`DDL_AUTO=update` creates the initial schema for this free deployment. Before
making production schema changes, add versioned migrations (Flyway or Liquibase)
and change it to `validate`.

## Deploy to Render

1. Push this directory to its own GitHub repository.
2. In Render choose **New > Blueprint**, connect the backend repository, and use
   the committed `render.yaml`.
3. Enter the requested secret values:

   | Variable | Value |
   |---|---|
   | `DB_URL` | Neon pooled Java/JDBC URL |
   | `DB_USERNAME` | Neon role |
   | `DB_PASSWORD` | Neon password |
   | `CORS_ORIGINS` | Exact Vercel origin, e.g. `https://hms-frontend.vercel.app` |
   | `BOOTSTRAP_ADMIN_PASSWORD` | Strong initial administrator password |

4. Deploy and confirm `https://YOUR-BACKEND.onrender.com/actuator/health`
   returns `{"status":"UP"}`.
5. Set the frontend's Vercel variable to
   `https://YOUR-BACKEND.onrender.com/api/v1` and redeploy the frontend.

On an empty database, `BOOTSTRAP_DATA=true` creates the initial administrator
using `BOOTSTRAP_ADMIN_USERNAME` and `BOOTSTRAP_ADMIN_PASSWORD`, plus two sample
doctors. Change the password after first login. The initializer does not replace
an existing user.

Free Render web services can sleep after inactivity, so the first request after a
quiet period can take longer. Neon can also suspend idle compute; both wake
automatically.

## Environment variables

See `.env.example` for a complete template. Render supplies `PORT`; the
application binds to it automatically. `JWT_SECRET` is generated by the Blueprint.

## Package architecture

The dependency flow is `Controller -> Service -> DAO -> Repository -> Entity`.
Controllers return DTOs and do not expose JPA entities directly.
